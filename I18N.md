## The story so far

Rankify is now multilingual at the chrome level. A little round 🌐 button sits beside the
"Start free" button in the navbar. Click it and you can switch between:

| Locale id | Language | Status |
|---|---|---|
| `en` | English | ✅ Default & complete (source of truth) |
| `hi` | हिन्दी | ✅ Nav translated — pages pending |
| `hinglish` | Hinglish (romanized, casual) | ✅ Nav translated — pages pending |

And because this is open source and we can't speak every language ourselves, there's a
**prebuilt GitHub issue form** (`.github/ISSUE_TEMPLATE/language_request.yml`) linked at the
bottom of that dropdown ("Want another language?"). Users pick a language, drop in three
sample translations, tick whether they can help — and a fully-structured issue lands in the
repo. New locales get onboarded from those.

## How the system works

One tiny module, no dependencies:

```
src/lib/i18n.ts
```

- `locale` — reactive ref (`'en' | 'hi' | 'hinglish'`), initialized from
  `localStorage['rankify-locale']`, falls back to `'en'`.
- `setLocale(l)` — sets + persists.
- `t(key)` — looks up the key in the active dictionary → English fallback → raw key.
  Because `t()` reads `locale.value` during render, templates re-render instantly on switch.
  No events, no providers, no magic.

### Adding strings

```ts
// src/lib/i18n.ts
const dicts = {
  en: { 'nav.cta': 'Start free', /* ... */ },
  hi: { 'nav.cta': 'मुफ़्त शुरू करें' },      // missing keys fall back to English
  hinglish: { 'nav.cta': 'Free mein shuru karo' }
}
```

```vue
<!-- any component -->
<script setup lang="ts">
import { t } from '@/lib/i18n'
</script>
<template>
  <button>{{ t('nav.cta') }}</button>
</template>
```

### Adding a whole new language (when an issue form arrives)

1. Add the id to `type Locale` and the `LOCALES` array.
2. Add its dictionary to `dicts` (partial is fine — English catches typos).
3. Add it to the dropdown `options` array in `src/components/AppNav.vue`.
4. Done. That's genuinely it.

## Ground rules (please keep these)

1. **English is the source of truth.** Never delete an `en` value; other dicts lean on it.
2. **Tone per locale:**
   - `hi` — warm, simple, school-friendly Hindi (वो भाषा जो बच्चे असल में बोलते हैं).
   - `hinglish` — casual romanized, like chatting with a friend. "Free mein shuru karo",
     not "Aap isko nishshulk arambh kar sakte hain". Keep it human.
3. **Brand voice lines** ("made for students, by people who remember roll numbers",
   "no red marks, only red circles") deserve real translations, not literal ones. Make them
   *feel* the same in your language.
4. **Don't translate:** the Rankify wordmark, "pdf→cbt", code/JSON snippets, API terms,
   file formats.
5. **Never break layout:** Hindi strings run ~15–30% longer. Check nav fit, button widths,
   and the exam-sheet mock after translating a section.
6. **Dates/numbers:** keep Latin numerals everywhere for now (matches the paper/exam vibe).

## Known landmines 🚧

- `src/pages/Review.vue` currently has a **pre-existing TS error being handled by another
  workstream** — not i18n's fault, don't chase it while migrating strings.
- Some strings live inside `v-html` icon blobs in `Home.vue` steps/features arrays — when
  translating those, edit the *text nodes*, leave the SVG alone.
- `document.title` / meta descriptions are static in `index.html` and `useHead()` calls.
  Localizing those is a nice-to-have; note it in your PR if you skip it.
